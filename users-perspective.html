User's Perspective

What this lab is, why you would use it, and what you get.

On this page

  1. What It Is
  2. Why You Would Use It
  3. Features You Get

What It Is

You get a virtual company network that runs on a single computer. It has a headquarters office and a branch office connected through a simulated internet provider, and it is built from real Cisco router, switch, and firewall software running in EVE-NG. Because nothing in it is physical, you can configure it, test it, break it on purpose, and rebuild it without risking a live network or buying any equipment.

Along with the network, you get step-by-step guides that walk you through building each part yourself, plus Python scripts that configure, back up, and check the devices for you. You can do a job by hand first, then see how automation does the same job faster and more consistently.

To run the lab, you need an x86 computer (Intel or AMD) with hardware virtualization turned on, and at least 16 GB of RAM. 32 GB is recommended for the full two-office network.

Why You Would Use It

If you work on a small IT team, one wrong command on your real network can take an office offline, and you probably don't have spare routers and switches to test on. This lab gives you a safe copy of a typical business network where you can rehearse a change, such as adding a VLAN or a new route, and see exactly what it breaks before you touch production.

If you are learning networking, classes and simulators teach you the commands, but they rarely show how a whole company network fits together. Here you work with the same Cisco IOS software used on real equipment, follow a design with real VLAN and IP plans, and troubleshoot real error messages. Each guide ends with a checkpoint, so you know whether your build works before you move on.

If you want to learn network automation, checking and backing up devices one at a time is slow and easy to get wrong. The included Python scripts log in to every device over SSH, check that the network is healthy, and save each configuration, so you can see why companies automate these tasks.

Features You Get

  • Headquarters network with VLANs: employee, server, voice, guest, and management networks kept separate on one switch, with a router routing traffic between them (router-on-a-stick). Available now.
  • Step-by-step build guides: every command is explained line by line, with a check after each step, a troubleshooting table, and the final configurations to compare your work against. Module 1 available now; more guides added as each module is built.
  • Branch office and WAN routing: a second office connected through a simulated internet provider, with OSPF sharing routes between the offices automatically. In progress.
  • Network services: a Linux server that hands out IP addresses (DHCP) and resolves names (DNS) for both offices. Coming next.
  • Automation scripts: Python and Netmiko scripts that push configurations, back them up to GitHub, and run checks such as pings and OSPF neighbor status after every change. In progress.
  • Network security: access control lists, a firewall at the branch, and site-to-site and remote-access VPNs. Planned for next quarter.
  • Monitoring dashboard: a page that shows which devices and links are up or down. Planned for next quarter.
  • Saved configurations and a README: everything you need to rebuild the lab from scratch and confirm that it works. Grows with each module.
