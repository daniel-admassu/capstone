Cisco IOS Configuration

Before building anything in EVE-NG, I needed to know what each Cisco command actually did, not just how to type it. Jeremy's IT Lab's free CCNA videos on VLANs were my main teacher for the switching side of Module 1. Part 2 covered trunk configuration, changing the allowed VLAN list with add and remove, the native VLAN, and router-on-a-stick. The lab video let me practice those steps in Packet Tracer first. Part 3 introduced Layer 3 switches and SVIs, which explained the management interface on my switch and showed me an alternative to router-on-a-stick for larger networks. I took notes on each video and checked my understanding against show command output in my own lab.

  • Jeremy's IT Lab. (n.d.-a). Free CCNA | VLANs (part 2) | Day 17 | CCNA 200-301 complete course [Video]. YouTube. https://www.youtube.com/watch?v=Jl9OOzNaBDU
  • Jeremy's IT Lab. (n.d.-b). Free CCNA | VLANs (part 2) | Day 17 lab | CCNA 200-301 complete course [Video]. YouTube. https://www.youtube.com/watch?v=iRkFE_lpYgc
  • Jeremy's IT Lab. (n.d.-c). Free CCNA | VLANs (part 3) | Day 18 | CCNA 200-301 complete course [Video]. YouTube. https://www.youtube.com/watch?v=OkPB028l2eE

Lab Platforms and Virtualization

The lab platform was the biggest obstacle of the quarter, and most of these resources came from troubleshooting it. I first read the GNS3 documentation for my original plan. When that plan failed, I compared alternatives, including FRRouting in Containerlab, and used Cisco Packet Tracer to practice my HQ design while I waited for a working lab. After my expert recommended EVE-NG, its Community Cookbook guided the installation, and its image-naming table and how-to guides explained why an image only appears in EVE-NG when its folder uses the right prefix and contains a virtioa.qcow2 file. The Broadcom and Microsoft articles explained why Windows Virtualization-Based Security and Memory Integrity block nested virtualization in VMware, which is what finally explained the error on the loaner laptop.

Network Automation and Monitoring

These resources support the second half of the project: managing the network with code and watching its health. The Netmiko documentation is my reference for connecting to Cisco devices over SSH from Python, sending commands, and reading their output, which is the foundation of my show-command, backup, and check scripts. The Grafana and Prometheus getting-started guide shows how metrics are collected and displayed on a dashboard. It is the starting point for the monitoring dashboard planned for next quarter, which my stakeholder rated as one of the two most important features.

  • Byers, K. (n.d.). Netmiko documentation. https://ktbyers.github.io/netmiko/
  • Grafana Labs. (n.d.). Get started with Grafana and Prometheus. Grafana documentation. https://grafana.com/docs/grafana/latest/fundamentals/getting-started/first-dashboards/get-started-grafana-prometheus/

Network Design and Routing

I used these resources to make sure the design rested on solid fundamentals before I configured anything. Cisco's Networking Basics course refreshed addressing, subnetting, and how devices on different networks reach each other through a router, the ideas behind my VLAN-per-subnet plan and the /30 WAN links. Practical Networking's article on routing between VLANs compared the options, from one router interface per VLAN, to router-on-a-stick, to a Layer 3 switch. It helped me understand why router-on-a-stick fits a small office like my HQ and where it stops scaling.

  • Cisco Networking Academy. (n.d.). Networking basics [Online course]. https://www.netacad.com/courses/networking-basics
  • Practical Networking. (n.d.). Routing between VLANs. https://www.practicalnetworking.net/stand-alone/routing-between-vlans/

Network Services: DHCP and DNS

These resources prepare Module 3, where a Linux server provides addresses and name resolution for both offices. Ubuntu's server documentation explains how DHCP hands out addresses and how it is set up on Ubuntu Server, the operating system my services server will run. Cloudflare's explanation of DNS walks through how a name is resolved step by step, which I need to understand before running my own DNS server. Together they also explain why DHCP needs a relay (ip helper-address) on the router before branch devices can reach a server at HQ.

  • Canonical. (n.d.). About DHCP. Ubuntu Server documentation. https://ubuntu.com/server/docs/explanation/networking/about-dhcp/
  • Cloudflare. (n.d.). What is DNS? | How DNS works. Cloudflare Learning Center. https://www.cloudflare.com/learning/dns/what-is-dns/
